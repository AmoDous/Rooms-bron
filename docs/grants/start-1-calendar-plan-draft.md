# Проект календарного плана НИОКР Rooms

Статус: черновик версии 0.1 на 12 месяцев. Даты, стоимость этапов и ответственные заполняются после открытия конкурса, формирования команды и утверждения сметы.

## Этап 1. Модель и экспериментальные алгоритмы

Срок: месяцы 1–6.

### Работы

1. Обследование процессов минимум трёх многокомнатных площадок и формирование обезличенного набора ограничений.
2. Патентно-информационный, научный и конкурентный поиск по интервальному планированию, рекомендациям и управлению загрузкой ресурсов.
3. Формализация ресурсов, жёстких ограничений, критериев качества и целевой функции.
4. Разработка схемы входных данных, правил валидации и паспорта происхождения наборов.
5. Расширение воспроизводимого стенда базовых стратегий и реализация исчерпывающего эталона для ограниченных задач.
6. Разработка и сравнение не менее двух экспериментальных вариантов многокритериального алгоритма.
7. Проверка корректности, полноты поиска и вычислительной сложности.
8. Подготовка промежуточного научно-технического отчёта.

### Результаты этапа

- отчёт об обследовании и поиске аналогов;
- формальная модель и проект целевой функции;
- версионированная схема обезличенных данных;
- эталонный алгоритм и две экспериментальные реализации;
- набор не менее 500 синтетических и обезличенных сценариев;
- протокол сравнительных испытаний;
- промежуточный НТО.

### Контрольные показатели

| Показатель | Значение |
| --- | ---: |
| Пилотные площадки с описанными ограничениями | не менее 3 |
| Помещения в обезличенном наборе | не менее 10 |
| Сценарии испытаний | не менее 500 |
| Нарушения жёстких ограничений | 0 |
| Совпадение допустимых вариантов с исчерпывающим эталоном | 100% на ограниченном контрольном наборе |

## Этап 2. Программный модуль и пилотные испытания

Срок: месяцы 7–12.

### Работы

1. Выбор алгоритма по результатам первого этапа и оптимизация его реализации.
2. Разработка механизма объяснения рейтинга и причин предложения альтернативного времени.
3. Реализация версионированного API и интеграция с экспериментальным контуром Rooms.
4. Проведение функциональных, контрактных, нагрузочных и негативных испытаний.
5. Проспективное пилотирование минимум на трёх площадках в течение 8–12 недель.
6. Сравнение с простыми стратегиями по точности времени, фрагментации, доле размещённых запросов и времени ответа.
7. Анализ ограничений метода и условий переноса на другие города и типы площадок.
8. Подготовка документации, заключительного НТО и материалов для регистрации программы для ЭВМ.

### Результаты этапа

- программный модуль многокритериального планирования;
- OpenAPI и JSON Schema интерфейсов;
- модуль объяснения результата;
- интеграция с прототипом Rooms;
- обезличенный пилотный набор и протокол испытаний;
- руководство разработчика и описание эксплуатации;
- заключительный НТО;
- комплект материалов для регистрации программы для ЭВМ.

### Контрольные показатели

| Показатель | Проектное значение |
| --- | ---: |
| Пилотные площадки | не менее 3 |
| Нарушения жёстких ограничений | 0 |
| Возврат допустимой альтернативы при её наличии | не менее 99% |
| Улучшение сводной целевой функции | не менее 10% относительно лучшей базовой стратегии |
| Снижение новых коротких интервалов | не менее 15% при сопоставимом сдвиге по времени |
| P95 расчёта запроса в контрольном окружении | не более 500 мс |
| Варианты с машиночитаемым объяснением | 100% |

## Приёмка

Каждый результат принимается только вместе с исходными данными, версией программного кода, параметрами запуска и протоколом проверки. Скриншот интерфейса без воспроизводимого теста не является подтверждением достижения показателя.

## Зависимости и точки решения

| Срок | Решение |
| --- | --- |
| До начала | Состав команды, права на задел, соглашения с пилотами |
| Конец месяца 2 | Утверждение модели ограничений и состава данных |
| Конец месяца 4 | Отбор экспериментальных алгоритмов для полного сравнения |
| Конец месяца 6 | Выбор метода для интеграции по результатам этапа 1 |
| Конец месяца 8 | Готовность API и плана пилота |
| Конец месяца 11 | Завершение сбора пилотных результатов |
| Конец месяца 12 | Приёмка, НТО и оформление РИД |

Пороговые значения считаются проектными до проверки на данных площадок. Если базовый эксперимент их не подтверждает, ТЗ корректируется до подачи, а не после получения гранта.
