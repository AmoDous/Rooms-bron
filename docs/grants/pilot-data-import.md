# Импорт обезличенных данных пилота Rooms

Инструмент нужен для первичного эксперимента по грантовой заявке. Он принимает три CSV-файла, проверяет их связи и формирует набор с контрольным хешем. Клиентские контакты для этого не нужны и не должны передаваться.

## Что запросить у площадки

1. `pilot-rooms-template.csv` — помещения, вместимость, рабочие часы, минимальная длительность, буферы и цена.
2. `pilot-room-blocks-template.csv` — занятые интервалы: подтверждённые и ручные брони, технические блокировки и временные удержания.
3. `pilot-requests-template.csv` — входящие запросы и результат обработки без имени, телефона и переписки клиента.

Первая строка каждого шаблона обязательна. Строку-пример нужно заменить реальными обезличенными данными. Несколько кодов помещений перечисляются через `|`, например `R001|R002`.

## Что запрещено включать

- имя, фамилию, телефон, email и логин клиента;
- адрес клиента, ссылки на профиль и контакты мессенджеров;
- текст сообщений, комментарии менеджера и свободные заметки;
- платёжные реквизиты, номера карт и ссылки на оплату;
- формулы Excel или Google Sheets.

Коды `V001`, `R001`, `Q0001` и `B0001` назначает сама площадка. Они не должны совпадать с телефонными номерами, внутренними идентификаторами клиента или заказа, по которым можно восстановить личность.

## Допустимые значения

- `block_type`: `confirmed`, `manual`, `technical`, `hold`;
- `start_step_minutes`: `15`, `30` или `60`;
- `request_source`: `phone`, `site`, `messenger`, `social`, `walk_in`, `other`;
- `final_status`: `new`, `pending`, `confirmed`, `rejected`, `cancelled`, `completed`, `unknown`;
- `decline_reason_category`: `busy`, `capacity`, `price`, `rules`, `no_response`, `client_changed`, `other` или пусто;
- логические поля: `true`, `false` или `unknown`;
- дата события: `YYYY-MM-DD`;
- время: `HH:MM`;
- момент создания, ответа и подтверждения: ISO 8601 с часовым поясом, например `2026-09-01T12:08:00+03:00`.

Для статусов `confirmed` и `completed` обязательно заполняются `confirmed_at`, `selected_start` и `selected_duration_minutes`. Предложенное время и его длительность также заполняются парой.

`recorded_at` показывает, когда занятость появилась в календаре. Если удержание или бронь позднее были сняты, момент снятия указывается в `released_at`; иначе поле остаётся пустым. Это позволяет восстановить состояние календаря на момент каждого входящего запроса без использования будущей информации.

## Проверка без сохранения

Из папки `server`:

```powershell
npm run grant:pilot-import -- --rooms ..\docs\grants\pilot-rooms-template.csv --blocks ..\docs\grants\pilot-room-blocks-template.csv --requests ..\docs\grants\pilot-requests-template.csv
```

При ошибке инструмент укажет таблицу, номер строки, колонку и причину. Исходные CSV при этом не изменяются.

## Формирование артефакта

После ручной проверки владельцем данных можно явно указать префикс результата:

```powershell
npm run grant:pilot-import -- --rooms <rooms.csv> --blocks <blocks.csv> --requests <requests.csv> --output ..\docs\grants\evidence\pilot-01
```

Появятся `pilot-01.json` и `pilot-01.md`. Существующие файлы не перезаписываются; ключ `--force` используется только после осознанной проверки новой версии.

## Важное ограничение

Автоматическая проверка отсеивает явные телефоны, email, ссылки, опасные колонки и ошибки структуры, но не понимает все возможные способы идентификации человека. До импорта представитель площадки и ответственный со стороны Rooms должны вручную просмотреть файлы. Сам импорт подтверждает состав набора, а не эффективность алгоритма: результаты испытаний оформляются отдельно и связываются с набором по SHA-256.
