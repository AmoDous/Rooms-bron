# Браузерные проверки Rooms

## Запуск

Из папки `server`:

```powershell
npm run test:e2e
```

На Windows используется установленный Microsoft Edge. На Linux и в CI сначала выполняется `npx playwright install --with-deps chromium`. Можно переопределить канал через `ROOMS_E2E_CHANNEL` и порт тестового сервера через `ROOMS_E2E_PORT` (по умолчанию 3199).

## Покрытие

Один набор запускается на ширинах 1440, 390 и 375 пикселей:

- выбор города без регистрации, переход из сценария в каталог;
- открытие помещения по прямой ссылке, смена даты и перезагрузка;
- запрет отзыва до посещения;
- вход клиента и отправка заявки с согласиями;
- двухфакторный вход партнёра, скрытый телефон до предоплаты и подтверждение заявки;
- переход клиента к серверной форме предоплаты без карточных полей Rooms;
- отказ при неправильном пароле;
- двухфакторный вход администратора и бухгалтера, восстановление кабинетов после перезагрузки;
- отсутствие горизонтального переполнения в проверяемых представлениях;
- медленное подключение API без временной доступности демо-формы бронирования.
- сохранение светлой/тёмной темы, доступность переключателя и контраст ключевых пар не ниже 4.5:1.

Каждый тест создаёт собственный временный API с репозиториями в памяти. `.env` не загружается, PostgreSQL не используется, реальные аккаунты и брони не меняются. Внешние карты, шрифты и провайдеры не вызываются. Пароли и TOTP в артефактах принадлежат только одноразовым тестовым аккаунтам.

## Отчёт и ограничения

HTML-отчёт: `server/playwright-report/index.html`. Снимки и трассировки: `server/test-results/`. Эти каталоги исключены из Git. В GitHub Actions отчёт хранится 7 дней.

Мобильный проект проверяет Chromium с мобильной шириной, но не заменяет отдельную проверку Safari на iPhone. Платёжный сценарий заканчивается перед отправкой оплаты: реальный банк, онлайн-касса, доставка писем и восстановление PostgreSQL проверяются отдельно на интеграционном окружении. Проверка отсутствия ошибок JavaScript не является аудитом всей доступности или безопасности сервиса.
